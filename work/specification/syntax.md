# work 语法

> 状态：草案。放在语境层的 `work/specification/`，等执行器落地、写法稳定后再升为正式规格。

work 是可执行单元的表达形式。一篇 work 文档里嵌一段 YAML，人和执行器读的是同一份。

本规格只定义「流水线」形态：有序步骤、跑完得一结果。业务对象从一个状态推到另一个状态的那种流程（状态机）另立一篇，两者共用「能力名 + 参数模板」两条约定。

## 载体

- work 文档是 Markdown，内含且仅含一个 ` ```yaml work ` 代码块
- 块内只描述流程，不出现任何平台命令
- 散文与块分工按「判定 / 命令」切：**块管判定**（步骤顺序、能力名与参数、判据、偏差、边界）；**散文管命令**（人执行时真正敲的命令与脚本）与取舍理由
- 同一个事实只写一处：判据与偏差只写在块里，命令与脚本只写在散文里
- 没有块的文档仍可读，执行器不认

## 顶层字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `work` | 是 | work 名，等于文件名去掉扩展名，小写短横线 |
| `标题` | 是 | 人读的名字 |
| `版本` | 是 | 整数，从 1 起；改步骤或判据加 1，加可选字段不加 |
| `输入` | 否 | 参数声明 |
| `前置` | 否 | 开跑前必须成立的检查 |
| `步骤` | 是 | 有序执行单元 |
| `校验` | 否 | 全部步骤跑完后的整体判据 |
| `偏差` | 否 | 现象 → 处置的对应表 |
| `不做` | 否 | 边界，执行器忽略，供人判断越界 |

## 输入

```yaml
输入:
  账号: { 必填: true }
  素材目录: { 默认: ./素材 }
  相册: { 可选: true }
  试跑: { 类型: 布尔, 默认: false }
```

- 类型：`字符串`（缺省）、`路径`、`布尔`、`整数`、`列表`
- `必填` 与 `默认` 互斥；`可选` 表示允许为空
- 引用写法 `{{输入.<名字>}}`，递归渲染——字符串、列表、字典都要替换
- 未声明的参数不允许在块内出现

## 前置

```yaml
前置:
  - 检查: 会话有效            # 能力名
    参数: { 账号: "{{输入.账号}}" }
    不成立: 提示先完成认证，不继续
```

`不成立` 是一句处置，执行器报错退出并原样输出这句话。

## 步骤

必填四项：`id`（本篇内唯一，小写短横线）、`做`（能力名）、`参数`、`执行者`（`系统` 或 `人`）。

可选三项：`判据`、`幂等`（`增量` 或 `否`，缺省 `否`）、`产物`（路径模式，供后续步骤与校验引用）。

```yaml
步骤:
  - id: 同步照片
    做: 从相册导出
    参数: { 账号: "{{输入.账号}}", 类型: 照片, 目录: "{{输入.素材目录}}/images" }
    判据: 退出码为 0
    幂等: 增量
```

`执行者: 人` 的步骤不写 `做`、`判据`、`幂等`，只写 `待办`——执行器不代劳，只把它列进待办清单：

```yaml
  - id: 确认颜色
    执行者: 人
    待办: 抽样打开转码后的视频，确认 HDR 片源未发灰
```

不许为了让流程跑通把人的步骤标成系统。人的步骤标成系统，等于给执行器编造能力。

## 判据

先只收四种，写法是 `<对象>: <句式>`；对象省略时指该步骤的产物：

| 句式 | 语义 |
|---|---|
| `退出码为 0` | 该步骤的能力调用成功返回（无对象） |
| `无 <模式> 残留` | 对象目录下不存在匹配该模式的文件 |
| `只含 <模式>` | 对象目录下所有文件都匹配该模式 |
| `数量与 <来源> 一致` | 对象目录的文件数与另一个目录或某个能力的返回值相等 |

```yaml
判据: "images: 无 *.HEIC 残留"
```

判据不成立，该步骤失败；失败不算完成，后续步骤不执行。`校验` 用同一组句式，在全部步骤跑完后执行。

新增判据必须同时写清语义与执行器如何判定，不许只给句式不给判定方法。

## 偏差

```yaml
偏差:
  - 现象: 退出码 0 但列不出相册
    处置: 网页端接受条款后重试
```

步骤失败时执行器按 `现象` 匹配给出 `处置`；匹配不上就原样报错，不猜。

## 能力

work 只出现能力名，参数名必须等于能力签名的参数名——不写别名，不用中文改写英文形参。

能力清单是执行器的输入，不进 work：

```yaml
能力:
  会话有效:     { 参数: [账号] }
  从相册导出:   { 参数: [账号, 类型, 目录, 相册, 试跑] }
  转为通用格式: { 参数: [类型, 目录, 附带来源] }
```

mock 实现与真实实现同签名——换实现不换流程，这是全部可测性的来源。

## 怎么算写对了

1. 块能过语法检查：字段齐、能力名在清单里、参数名对齐签名、模板引用的输入都声明过
2. 散文与块不重复：判据与偏差只在块里，命令与脚本只在散文里，取舍理由不写成步骤
3. 人的步骤确实标成人
4. 把执行器去掉，散文里的命令能让人把整条流程做完

## 示例

下面是最小可跑示例，只用来说明字段如何组合，不追求与任何一篇实际 work 逐字相同。

```yaml work
work: export-icloud-photo
标题: 导出 iCloud 照片
版本: 1

输入:
  账号: { 必填: true }
  素材目录: { 默认: ./素材 }
  相册: { 可选: true }
  试跑: { 类型: 布尔, 默认: false }

前置:
  - 检查: 会话有效
    参数: { 账号: "{{输入.账号}}" }
    不成立: 提示先完成认证，不继续

步骤:
  - id: 同步照片
    做: 从相册导出
    参数: { 账号: "{{输入.账号}}", 类型: 照片, 目录: "{{输入.素材目录}}/images", 相册: "{{输入.相册}}", 试跑: "{{输入.试跑}}" }
    判据: 退出码为 0
    幂等: 增量

  - id: 同步视频
    做: 从相册导出
    参数: { 账号: "{{输入.账号}}", 类型: 视频, 目录: "{{输入.素材目录}}/videos", 相册: "{{输入.相册}}", 试跑: "{{输入.试跑}}" }
    判据: 退出码为 0
    幂等: 增量

  - id: 照片转码
    做: 转为通用格式
    参数: { 类型: 照片, 目录: "{{输入.素材目录}}/images" }
    判据: "images: 无 *.HEIC 残留"

  - id: 视频转码
    做: 转为通用格式
    参数: { 类型: 视频, 目录: "{{输入.素材目录}}/videos", 附带来源: "{{输入.素材目录}}/images" }
    判据: "videos: 无 *.MOV 残留"

  - id: 确认颜色
    执行者: 人
    待办: 抽样打开转码后的视频，确认 HDR 片源未发灰

校验:
  - "images: 只含 *.jpg"
  - "videos: 只含 *.mp4"
  - "images: 数量与 相册条数 一致"

偏差:
  - 现象: 退出码 0 但列不出相册
    处置: 网页端接受条款后重试
  - 现象: 视频颜色发灰
    处置: 片源为 HDR，转码前需 tonemap

不做:
  - 选题、选图、文案与标签、发布
```

## 不做什么

- 不定义状态机形态（对象推进另立一篇）
- 不定义能力实现，块内不许出现平台命令
- 不定义调度：定时与常驻由外部工具负责，work 只管跑一轮
- 不定义渲染与排版：散文部分怎么写不归本规格管

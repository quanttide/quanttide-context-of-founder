# 产物契约

> 状态：草案。与同目录 `task-blueprint.md`、`artifact.md` 配套：`task-blueprint.md` 定义一件事怎么做，`artifact.md` 定义跑完之后存在什么，本文档定义那份产物**长成什么样算合格**。

产物契约是一份可判定的合格线。它只管「什么算过」，不管产物是什么、叫什么、怎么生成。

单独成篇的理由是复用：同一种产物被多处引用时共用一份契约，约束改一次全部跟着变；写在每一处就会有两处真源，改一处漏一处就自相矛盾。

## 三条禁令

1. **不许愿池。** 凡是落不成可逐项比对的条目一律不进契约（「图要好看」「文案要通顺」），另立人判清单。每条约束必须带「谁判」，人判的也要显式标出，不假装都能交给机器。
2. **不两头写。** 判据只存在契约里。产物定义只写是什么、在哪、什么格式、多少；步骤只写靠什么做、谁做。
3. **不管名字。** 产物叫什么归产物自己，契约只规定形状与合格线。

## 结构

| 字段 | 必填 | 说明 |
|---|---|---|
| `contract` | 是 | 契约名，等于文件名去掉扩展名，小写短横线 |
| `标题` | 是 | 人读的名字 |
| `适用产物` | 是 | 这份契约约束哪一类产物 |
| `版本` | 是 | 整数，从 1 起；改约束加 1 |
| `约束` | 是 | 约束条目列表，至少一条 |
| `幂等` | 否 | `逐字节相同` 或 `不要求`，缺省 `不要求` |
| `例外` | 否 | 允许不成立的场合，必须写明判据与处置 |

## 约束条目

每条四项，缺一项不成立：

| 项 | 含义 | 取值 |
|---|---|---|
| 对象 | 约束落在哪 | 产物的某个位置，或某个模式 |
| 判据 | 合格的条件 | 四句式之一（见下） |
| 谁判 | 由谁作出判定 | `机器` / `智能体` / `人` |
| 处置 | 不成立时怎么办 | `停` / `跳过` / `报错` |

判据沿用四句式，写法是 `<对象>: <句式>`：

- `只含 <模式>`：该位置下所有文件都匹配
- `无 <模式> 残留`：该位置下不存在匹配的文件
- `数量与 <来源> 一致`：文件数与来源计数相等
- `逐字节相同`：与上一次结果完全相同（仅在 `幂等: 逐字节相同` 时可用）

`谁判` 为 `机器` 时，判据必须是上述四句式之一；为 `智能体` 或 `人` 时，判据写成一句话判准，处置只能是 `跳过` 或 `报错`——人判的条目不能作为阻断流水的前置条件。

## 示例

```yaml artifact-contract
contract: material-set
标题: 素材集合合格线
适用产物: 素材集合
版本: 1

约束:
  - 对象: "{{产物.位置}}/images"
    判据: "只含 *.jpg"
    谁判: 机器
    处置: 停
  - 对象: "{{产物.位置}}/videos"
    判据: "只含 *.mp4"
    谁判: 机器
    处置: 停
  - 对象: "{{产物.位置}}/images"
    判据: "数量与 相册照片条数 一致"
    谁判: 机器
    处置: 报错
  - 对象: "{{产物.位置}}/videos"
    判据: "数量与 相册视频条数 一致"
    谁判: 机器
    处置: 报错
  - 对象: "{{产物.位置}} 的抽样条目"
    判据: 画面颜色不发灰、方向正确
    谁判: 人
    处置: 跳过

幂等: 逐字节相同

例外:
  - 相册未在网页端完成初始化时，数量口径不成立；按偏差处置，不记违约
```

## 与产物定义的分工

产物定义回答四问：是什么、在哪、什么格式、多少。契约回答第五问：合格线在哪。

判断有没有越界，用一条验法：**把契约删掉，产物定义仍完整成立；把产物定义删掉，契约失去对象。** 前者成立说明契约没有重复产物定义，后者成立说明契约确实依附于产物。

## 自检

1. 每条约束四项齐全，判据是四句式之一或显式的人判一句话
2. `谁判: 机器` 的条目没有一句人话式判据
3. 产物定义里没有判据，契约里没有位置与数量的重复陈述
4. 例外条目写明判据与处置，不是一句「特殊情况除外」

## 不做什么

- 不定义产物怎么生成，那是步骤与能力的事
- 不定义产物的名字与类别
- 不定义归档与封存
- 不在本版规定契约之间的继承或组合：等出现两处复用同一契约的实例再议

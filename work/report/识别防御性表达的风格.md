这个需求其实非常契合传统 NLP 的舒适区——因为”AI 防御性输出“本质上是一种风格特征，而风格特征恰恰是词典法、规则引擎的强项。大模型在这里确实是最差的选择。下面按”规则纯度“从高到低给你排一遍，并标注各自的适用位置。
一、方法论全景（按规则纯度排序）
① 词典法 + 加权打分（最推荐，核心骨架）
这是整个方案的灵魂，参照系就是经典的 VADER——一个完全手工构建情感词典 + 一堆启发式规则的打分器，零训练、全可解释。你完全可以照着做一个”DefensiveVADER“：
1. 按”防御性毛病“的类别建分词典，每类列种子词（下面给种子清单）
2. 每个词赋一个权重（可以人工定，也可以用语料统计校准）
3. 句子得分 = Σ(命中词权重 × 位置修饰系数)，再按句长归一化
4. 全文得分 = 各句加权汇总，输出一个”防御度“分数 + 命中明细
这个结构的好处：输出不是黑箱分类，而是”哪一句、命中了哪条规则、扣了多少分“，天然就是你要的案例提取器。
② 正则 + 模式匹配（规则引擎层）
词典管词，正则管句式。防御性输出的很多特征是固定句法模板，正则就能抓住：
# 让步-转折防御（最高频特征）
(虽然|固然|当然|的确).{0,30}(但是|但|不过|然而|可是)
# 免责声明模板
(仅供参考|不构成.{0,6}(建议|意见)|请.{0,6}(咨询|联系).{0,8}(专业|医生|律师))
# 先认错再解释
(抱歉|对不起|不好意思|我的错).{0,50}(因为|由于|实际上|但是)
# AI 自指
(作为一?个?AI|我只是一?个?(AI|语言模型|程序)|无法(完全)?保证)
# 家长式叮嘱
(提醒您|请注意|建议您|切记|务必)
③ 多模式匹配引擎（工程层）
词典到了几百上千条时，逐条 in 判断太慢，上 Aho-Corasick 自动机（Python 的 pyahocorasick / acora）：一次扫描文本同时匹配全部词典条目，O(文本长度) 复杂度，是工业级敏感词引擎的标准做法。这一层纯粹是性能问题，方法论上还是词典法。
④ 中文 LIWC 式类别计数（最贴合需求的传统范式）
LIWC（Linguistic Inquiry and Word Count）是你这个需求的”祖师爷级“方法论——心理学界用词类计数分析文本风格做了三十年，核心思想就是把词分入心理/功能类别，然后统计各类的频率密度而不是有无。你可以自建一个中文防御性 LIWC 词典，统计指标例如：
• 每千字命中”让步连词“次数
• 一人称代词密度（”我“高频 = AI 自我指涉多）
• ”建议/提醒/注意“类祈使动词密度
• 句均长度 + 长句（>60 字）占比——防御性输出显著偏长
• 模糊限制语密度，这是语言学里对 hedging 的正式称呼，有现成英文研究可参考翻译建表
⑤ 词表自动扩充（半统计，仍然传统）
种子词典会有漏网之鱼，用统计共现扩表，不需要任何神经网络：
• PMI（点互信息）：在目标语料里算”哪些词总是和’仅供参考‘’不好意思‘共现在同一句“，PMI 高的候选词人工审核后入表
• Log-likelihood ratio：对比”AI 回复语料 vs 人类回复语料“，差异显著度最高的词就是防御性标志词——这一步顺带完成了特征验证
• TF-IDF 找 AI 语料的特征词也行，但 PMI/LLR 更适合”找同类词“这个目的
⑥ 经典机器学习（兜底，可解释）
如果词典+规则到顶了想再提一档准确率，用逻辑回归 / 朴素贝叶斯 / 线性 SVM，特征全部是手工构造的（词典命中数、句式命中数、LIWC 密度、句长分布、标点特征）。逻辑回归的系数本身就可以”翻译回规则“——权重 0.8 的特征等于一条高分规则，依然可解释可审计。不要上深度模型，你的样本量（几千条标注顶天）也喂不饱它。
明确不建议的：词嵌入句向量 + 分类器（虽然传统但不可解释）、bertology 小模型（需要 GPU 和标注量）、任何 prompt 大模型的方案。
二、种子词典清单（按防御性毛病分类，直接可用）
类别	种子词示例
模糊限制语	或许、可能、大概、也许、通常、一般来说、在一定程度上、某种意义上、相对、比较
免责声明	仅供参考、不构成建议、请注意、需要说明的是、值得注意的是、提醒、视情况而定
AI 自指	作为一个AI、语言模型、我无法、我不能、我的知识截止、我没有能力
先认错再解释	抱歉、不好意思、我的理解可能有误、感谢你的指正、你说得对
让步转折	虽然…但是、当然…不过、确实…然而、无可否认
家长式叮嘱	建议、务必、切记、请注意、一定要、千万别、强烈建议
立场套话	这并不代表、这并不意味着、具体情况需、因人而异
结构性冗余	首先/其次/最后、总而言之、综上所述、总的来说

四、建议的流水线
原文 → 分句 → 句级四路并行：
  ① AC自动机词典命中
  ② 正则句式命中
  ③ LIWC式密度统计
  ④ 结构特征（句长/一人称率/标点）
→ 句级防御度得分（加权求和）
→ 阈值切分：得分高句 → 抽出 + 标注命中规则ID
→ 全文聚合得分 + 命中报告
这条流水线每一环都可解释、可人工修正、可增量加规则，产出的”命中明细“本身就是你要收集的案例库，不用再做一层转换。
最后一个实操建议：先把 ①②③ 做起来就够用了，权重初始值全部人工拍（比如免责声明 2.0 分、模糊限制语 0.5 分），跑几百条真实对话校一轮就能到很好用的程度。规则引擎方法的优点就在这里——冷启动几乎零成本，错了随时改。要不要我帮你把其中某一类（比如模糊限制语或免责声明）的完整正则规则集和权重方案写出来？

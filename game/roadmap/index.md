本次讨论精华总结 + 全局路线图
一、讨论收敛出的核心决策链
一路讨论从底层架构走到验收系统，每一步都建立在前一步之上，最终拧成一条完整的决策链：
1. 回合制是正解不是妥协——WEGO 结构（同时下令→服务器结算→各自读报）恰好是指挥官层的正统形态：命令延迟、等报告、异步对局全部天然成立，企业架构从“限制”变成“顺水推舟”；
2. 单机先行——AI 嵌入本地客户端，砍掉联网复杂度，保留全部玩法结构；确定性引擎在单机下照样值钱（校准、回放、将来转联网的最低成本路径）；
3. 两个运行时子系统 + 一份契约——指挥部系统（智能全在这）和战棋引擎（刻意做哑，只认命令只说真话）之间只有两条接口：结构化命令流上行、确定性事件流下行。中间层（迷雾/信念/翻译）以“认知模块”形式落在指挥部内部，不设第三个子系统；
4. 指挥部系统是主产品——引擎是哑插件，玩法智能（命令翻译、认知、敌军 AI）全在指挥部侧；敌军 AI 与玩家走完全相同的契约和迷雾管线，公平靠结构不靠自觉；
5. CLI 先行、驱动层逐步换人——玩家是一个接口不是一个界面：AI 脚本 → 你本人用 CLI → 新人读文本 → Flutter，核心机制在换方向盘的过程中始终不变。
二、自动化测试体系（浓缩版）
四类测试、四个层级，各有分工：
层级	方式	测什么	归属
确定性测试	同种子跑两遍，hj diff 比对	引擎可复现性	CI 每次提交
契约测试	schema 校验 + 非法样本负向测试	接口格式与拒绝能力	CI 每次提交
夹具回归	微型想定 vs 手写期望结果	每个机制的行为正确性	CI + 每新增机制补一个夹具
分布测试	hj batch 100 种子出统计	参数不荒谬、改动漂移可见	每次调参后
迷雾/AI 断言	report vs truth 自动比对、决策可追溯	迷雾生效、AI 无上帝视角	CI（阶段 3 起）
人类协议	L2 困惑清单 / L3 复述测试 / L4 对照表	可理解性、体验	每轮迭代
三条铁律：金标准人工把关（期望结果必须人复核）；AI 测试者不得走捷径（敌军 AI 只能读投影，与玩家同路）；人类测试不可省（困惑清单与 CI 同等对待）。

关键并行关系：阶段 2 与 3 并行（阶段 1 的假桩买来的自由）；验收系统始终领先本体半步——“本体换真实现之前，验收能力先长出来等着”。
三条全程纪律：
1. 确定性检查进 CI，diff 非空即红——地基中的地基；
2. 界面/测试者永远不直读引擎真相——迷雾是结构不是滤镜；
3. LLM 不进结算闭环——只碰事件流之外的文本层。
第一步动手清单（今天就能开始）：
• 本体侧：事件类型表（契约的心脏）+ 命令/事件 JSON Schema；
• 验收侧：3 个微型想定夹具 + 金种子 + hj validate。
一句话总结这个项目的方法论：先让“答案”存在（金标准），再让“考试”成立（断言），再让“考生”逐步换人（AI→你→真人）——游戏本体、验收系统、驱动层级三条线同步推进，每一步都有可运行、可验证、可玩的东西在手。

指挥部系统路线图
对齐路线图四个阶段，只列指挥部侧的活。核心细节保留，次要的压缩成一行。
阶段 1：骨架（1–2 周）
做三样东西：
1. 回合状态机——下令/结算/战报三相位，规定所有模块的调用时序。最先写，其他一切都挂在它上面；
2. 认知数据结构——情报账本（append-only，带出处/可信度/时效字段）+ 信念状态（敌军各建制的估计位置/实力/置信度）两个 schema 定稿；
3. 假桩闭环——命令编辑器桩（一道纵队命令 → if-else 展开成引擎格式）→ 引擎桩 → 事件流进认知模块桩 → 弹一条战报。
验收：下令到读战报的闭环走通；同样的命令跑两次结果逐字节一致。
阶段 3：心脏（2–3 周，与引擎真实现并行）
做两样东西：
1. 认知模块真实现——按四步做：过滤（可见性）→ 延迟（按通信距离排送达）→ 失真（报告偏差规则表）→ 信念重算（新情报触发，可推翻旧判断）；
2. 敌军指挥官 v0——读自己的信念状态 + 2–3 个性格参数（谨慎度/冒进度/信任阈值）→ 规则决策 → 走同一个翻译器和契约。它没有上帝视角，这是结构性公平。
验收：导出“引擎真相”和“玩家所见”两份日志，人工能指出迷雾生效；敌军 AI 每个决策能回答“它当时信了什么”。
阶段 4：三甲板（2 周）
1. 参谋翻译器升级——if-else 换成规则模板系统，两级展开（最终命令→纵队→引擎命令），附回执机制（参谋的理解反馈给玩家确认）；
2. 结构化追问——点选任何敌军建制弹出参谋评估卡（估计/置信度/依据），即“问参谋”，纯查询接口；
3. 界面纪律落地——要图只读信念状态，引擎状态包对界面层不可 import（红线写成代码约束，不靠自觉）；
4. 存档/回放——全量状态 + 命令 + rng_log 重演，要求各模块从本阶段起状态全部可序列化。
验收：同一局中途切换甲板层级无缝衔接。
阶段 5：增量（闭环稳定后）
• LLM 接入，位置只限两处：战报文本润色、参谋对话化（把结构化追问升级成自然语言）；
• 敌军决策从规则换可调参模型；性格参数从侧写卡全量导入。
三条纪律（全程有效）
1. 引擎状态永远不可被界面直读——迷雾是结构不是滤镜；
2. 确定性检查进 CI——金种子回归，diff 非空即红；
3. LLM 不进结算闭环——只碰事件流之外的文本层。
动手顺序：状态机 + 两个 schema 先行（其他模块的输入输出都挂在这三样上），然后一切围绕假桩闭环收口——闭环通了，后面每个阶段都只是换真实现，结构不再动。

# 豫东战役 · 作战指令模板（战棋游戏用 v0.1）

> 用途：把「指挥部下达作战命令 → 作战机构拆解执行 → 兵棋推演结算」做成一条数据链。
> 母本：1948.6.15《作战部署命令》及豫东系列调整令、停战电；本文件为**游戏化改写**，地名、时间、番号已坐标化/回合化，正式上线前请回《粟裕军事文集》校订原文。

---

## 一、设计前提

作战命令不是文章，是**结构化指令**。它自带的字段恰好能直接映射三层链路：

| 原令部件 | 游戏层 | 是否可执行 |
|---|---|---|
| 签发人 / 令号 / 时间 | 指挥部元数据 | 否，但决定合法性 |
| （甲）敌情判断 | 事件牌 / 敌 AI 权重 | 否 |
| （乙）友邻协同 | 不可指挥的外部变量 | 否 |
| （丙）我决心 | **本关胜利条件切换点** | 是（唯一） |
| （丁）任务区分 | 拆成各纵队执行单 | 是 |
| 开进 / 统一发起时间 | 回合时间轴 | 是 |
| 作战分界线 | 地图上的分割线 | 是 |
| 「任务不变（按前令）」 | **令间指针 ref** | 自动继承 |

核心玩法：**偏差**。玩家（作战机构）可以改部署，但每次偏离都要记账，推演结算时按「令—执行—结果」出复盘战报。

## 二、字段定义（Order 对象）

```
Order {
  meta: {
    order_id        : string   // 令号，如 "YD-0615-01"，供 ref 引用
    title           : string   // 作战部署命令 / 合围令 / 调整令 / 停战令
    issuer          : string[] // 签发主体（粟裕、陈士榘、张震…）
    issued_at       : string   // 游戏内时间 "T0 12:00"
    kind            : enum     // PRESET | ATTACK | ADJUST | CEASE
    ref             : string?  // 指向上一令；非空时 sec_d 可整体继承
    report_policy   : enum     // REPORT_FIRST | ACT_THEN_REPORT（先斩后奏）
    effective       : string   // "即刻" / "T+n 黄昏"
  },
  sec_a : EnemyEstimate      // 敌情判断 → 只喂事件牌与敌 AI
  sec_b : NeighborCoord      // 友邻协同 → 中野、军委、地武，玩家不可调
  sec_c : Intent             // 我决心 → 覆盖本关 victory_condition
  sec_d : TaskUnit[]         // 任务区分 → 拆解给作战机构
  time_marks: {
    open_move   : string     // 开进回合（原「六日黄昏由现地开进」）
    h_zero      : string     // 统一发起回合（原「八日晚统一发起战斗」）
  },
  boundary  : Line[]         // 作战分界线，坐标化
  deviation : DeviationLog[] // 玩家改动记录，推演后写回
}
```

```
TaskUnit {
  unit_id        : string   // 三纵 / 八纵 / 十纵并广纵…
  command_chain  : string   // 归陈唐 / 归宋刘 / 野司直接指挥
  verb           : Verb     // 见第三节枚举
  target         : Coord|UnitId
  start_at       : string   // 回合
  end_condition  : string   // 达成 / 时间到 / 触发事件
  support        : string[] // 附特纵炮兵、东兵团炮兵团…
  constraint     : string?  // 「第一日暂不使用」「任务不变」
}
```

## 三、任务动词枚举 → 结算规则

| 动词 | 结算对象 | 玩家可改的余地 | 失败后果 |
|---|---|---|---|
| `包围/合围` | 目标格相邻控制数 ≥ N | 合围口选在哪 | 敌突围，退路判定失败 |
| `攻占` | 据点耐久 + 攻坚值 | 投入几纵、是否留预备 | 顿挫，疲劳 + |
| `阻援/坚决阻击` | 指定线生成阻援场，敌援移动力 −X | 阻援线前后挪 | 援敌穿透，主攻受夹 |
| `钳制/攻势钳制` | 不判歼灭，只加敌「错觉值」 | 造多大攻城态势 | 敌识破，分兵权重回正 |
| `分割` | 切断两敌部连通 | 切哪条接合部 | 两部靠拢，合围破产 |
| `截击/截断靠拢` | 移动中敌军触发遭遇战 | 是否跑步转向 | 目标合流，难度升级 |
| `破击（交通）` | 敌补给/增援速率 −X | 破哪段路 | 援敌提前到场 |
| `待机` | 不消耗，保留主要突击方向 | 何时解锁 | 错过窗口 |
| `北撤/休整` | 脱离接触，结束关卡 | **是否主动停手** | 贪战 → 战损失控 |
| `继承(ref)` | 直接载入前令 sec_d | 只能改标注为可改的项 | 无 |

> 「钳制」和「阻援」必须分开做：前者是骗，后者是挡。豫东里这两类任务同时存在，全挤成「攻击」按钮就没味道了。

## 四、可推演回合表（四关骨架）

真实日期压成回合，一关一次**决心切换**。

| 回合 | 史料锚点 | 下达令 | 决心切换 | 玩家决策点 | 结算重点 |
|---|---|---|---|---|---|
| T0 | 6.15 12时 | 部署令：转豫东、陈唐打开封 | 放弃打整五军 → 攻开封 | 批不批「先斩后奏」 | 开进路线、阻援线布置 |
| T1 | 6.16 晚 | 围开封 | 攻城 | 三/八纵攻坚 vs 一/四/六纵阻西援 | 据点判定 |
| T2 | 6.22 | — | 弃城打援 | 战利品要不要、转不转睢杞 | 战果 / 疲劳值 |
| T3 | 6.27 夜 | 合围区寿年令 | 歼区兵团 | 合围口选哪 | 分割判定 |
| T4 | 6.28 未 | 调整部署令 | 敌收缩 → 重排突击集团 | 改指挥链（归十纵宋司令） | 分界线重算 |
| T5 | 7 月初 | 截二十五师令 | 转打黄百韬 | 是否继续加码 | 援敌迫近压力 |
| T6 | 7.7 | 停战/北撤令 | **放弃续歼** | 主动停手（核心关） | 保存兵力 vs 贪战损 |

**事件牌（挂在时间轴上）**
- `请示不及，已令各部执行`：+主动权 / −政治点数，军委下回合追认
- `敌收缩`：强制进入调整令，作废部分 sec_d
- `援敌迫近（邱 / 黄 / 胡琏）`：压力计时器 +1
- `友邻钳制生效`：中野方向减援，sec_b 兑现
- `疲劳累积`：连续两回合不待机，攻坚值递减

**胜利条件不是「全歼」**：T6 能按令北撤且保住建制 = 优；贪到被援敌咬住 = 劣。这一关才是指挥决策感所在。

## 五、游戏内令文样例（UI 可直接渲染）

> **华东野战军作战部署命令（节选）**
> 令号 YD-0615-01 ｜ T0 12:00 ｜ 签发：粟裕、陈士榘、张震 ｜ 先斩后奏
>
> **（甲）** 整五军集结鲁西南，正面寻战不利；开封守备空虚。
> **（乙）** 中野方向牵制平汉线之敌，地武破击陇海。
> **（丙）** 决心：放弃在鲁西南硬打整五军，转兵豫东，先取开封，尔后待机打援。
> **（丁）**
> 1. 三纵、八纵 → 归陈唐指挥，`包围·攻占` 开封，`T1 黄昏` 完成合围。
> 2. 一纵、四纵、六纵 → 转曹县东南，`阻援` 西援之敌，野司直接指挥。
> 3. 其余各部 `待机`，保留为主要突击方向。
>
> 开进 `T0 黄昏` ｜ 统一发起 `T1` ｜ 分界线见地图 Layer-02
> ⚠ 本令未经请示已下发，待军委追认。

渲染建议：`verb` 高亮成可点按钮，`ref` 显示成「继承前令」链接，`time_marks` 钉在回合条上，玩家改动自动进 `deviation`。

## 六、落库建议

1. 令 = **数据对象**，不要存成整段字符串；`sec_d[]` 直接驱动单位指令队列。
2. `ref` 实现「任务不变（按战字××号预备命令）」，避免每关重写部署。
3. `time_marks` 是回合推进器，`h_zero` 到点统一结算所有 `start_at <= h_zero` 的任务。
4. `deviation` 同时喂战报系统和复盘回放：令怎么写、实际怎么打、差在哪，一眼可见。
5. 史料层与游戏层分离：`source_note` 字段存原文出处，改写层单独维护，别把坐标化地名回写进史料。

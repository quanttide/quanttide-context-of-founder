契约实现路线图
总体思路：契约本身当作一个独立产品来做——先定死格式，再让两个系统各自对着假桩开发，最后合拢。每个阶段都有可运行的东西，而不是“文档写完等联调”。
阶段0 → 阶段1 → 阶段2 → 阶段3 → 阶段4
定格式   打通闭环   填真引擎   插认知模块   三甲板展开
 1周      1-2周      3-4周      2-3周       2周+
阶段 0：契约格式冻结（约 1 周）
目标：接口①②的 schema 定稿，写成一份契约文档 + 一套校验工具。
• 命令 schema：{turn, side, orders[]}，order 的字段集（unit、action、目标、路径约束、时限、中止条件）一次定全——宁可先放超集字段也不留扩展口子，后期加字段是契约的最大杀手；
• 事件 schema：先枚举第一版事件类型表（move / contact / combatresult / attrition / supply / capture / reportgenerated…），每类定字段，rng_log 强制入契约；
• 单位标识与地形引用：双方共用的 ID 体系（OOB 番号 ID、地图节点 ID）——这是最容易扯皮的部分，先冻结；
• 确定性条款写进契约：所有随机必须带种子引用，事件流里禁止出现未解释的随机性。
产出：contract.md + JSON Schema + 一个校验 CLI（任何一方交付的命令/事件文件可一键验证）。
验收标准：拿一份手写的假命令文件和假事件流，能通过校验工具且字段无歧义争议。
阶段 1：假桩闭环（1–2 周）
目标：两个系统都用假实现跑通一个回合的完整生命周期。
• 引擎桩：不做真结算，收到命令后按硬编码规则生成事件流（比如所有 move 单位原样回显移动事件），确定性、带 rng_log 占位；
• 指挥部桩：界面上下达一道纵队命令 → 命令翻译用 if-else 模板展开成引擎格式 → 收事件流 → 要图上棋子动一下 → 弹出一条战报。
验收标准（这是全程最重要的一次验收）：
1. 从“下令”到“读到战报”的闭环走通，全程无人工干预；
2. 同样的命令 + 同样的种子，跑两次，事件流逐字节相同；
3. 中途替换任一侧为真实现，另一侧零改动——用桩的交换来证明契约成立。
这一阶段结束时，两人（或一个人的两个模块）从此可以并行开发互不阻塞。
阶段 2：真引擎填入（3–4 周，与阶段 3 可并行）
目标：引擎桩换成真结算，契约字段在真实压力下回炉。
• 实现优先级：机动 → 接敌判定 → 战斗结算 → 损耗与补给 → 撤退/溃散；
• 每实现一类结算，对照阶段 0 的事件类型表回填真实字段——这一步必然发现 schema 的缺陷（缺字段、粒度不对），修订走契约版本号（v0.x 期间随便改，冻结后走 changelog）；
• 想定数据接入：一个睢杞段小想定（双方 5–8 个纵队级单位、OOB、地图）从参数卡格式导入；
• 建立回归基线：一组金种子 + 金命令集，每次改动跑一遍比对事件流 diff——确定性引擎的 CI 就是这个。
验收标准：金种子下，同一想定 AI 打 AI 跑 50 局，统计分布稳定；事件流无未定义类型。
阶段 3：认知模块填入（2–3 周）
目标：完整事件流 → 失真投影，迷雾系统第一次活起来。
• 按之前定的四件事实现：过滤（可见性）→ 延迟（通信排程）→ 失真（报告偏差规则表）→ 信念状态（v0 就是一个结构化的敌情判断表）；
• 双实例对称：玩家侧和敌军 AI 侧跑同一个模块、不同配置；
• 敌军 AI v0 接上：读自己的信念状态 + 性格参数（2–3 个：谨慎度、冒进度、对情报的信任阈值）做决策，输出引擎格式命令——它和玩家走完全相同的接口①②，这是公平性的结构性保证。
验收标准：同一局，导出“引擎真相日志”和“玩家所见战报”，人工比对能明确指出迷雾生效（玩家图上有假/缺/迟的信息）；敌军 AI 在信息不全时做出的决策可解释（能回答“它当时信了什么”）。
阶段 4：三甲板展开与可玩版本（2 周起）
目标：契约不再变化，甲板成为界面层的事。
• 命令翻译从 if-else 换成规则模板系统（最终命令 → 纵队命令 → 引擎命令的两级展开）；
• 纵队甲板做到完整可玩；最终命令甲板作为翻译器的减法版本顺手而出；战棋甲板仅验证命令直通（界面可最后做）；
• 单人完整战役一局跑通：约 20–30 个回合，能打赢也能打输。
验收标准：滑杆测试——同一局中途切换甲板层级，命令展开和战报投影无缝衔接；AI 打 AI 全自动跑通 1000 个种子不出未处理异常（校准管线就此成立）。
贯穿全程的三条纪律
1. 契约变更走版本号：阶段 2 是 schema 的最后修订窗口，进阶段 3 后任何字段变更必须双端同步改桩——宁可忍到下个版本；
2. 确定性检查进 CI：每次提交自动跑金种子回归，diff 非空即红——这是整个架构的地基，值得最重的保护；
3. LLM 不进闭环：前四个阶段 AI 参谋全部用规则实现，LLM（战报润色、口供生成）等闭环稳定后作为阶段 5 的增量接入，位置只允许在“事件流之外的文本层”。
